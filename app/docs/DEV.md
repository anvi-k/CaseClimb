# Developer notes

Poscere is a telehealth simulator for health-professions education. Students hold a video-style
visit with a virtual patient (left) beside a live electronic chart (right), then get rubric
feedback tied to transcript evidence. Faculty build patients, courses and multi-clinician care
journeys. Product framing: every encounter is a telehealth video visit.

## Stack

- Next.js 16 (App Router, React 19, TypeScript, Tailwind v4). **This Next.js has breaking changes**:
  `params`/`searchParams` are Promises, `cookies()` is async. When unsure read
  `node_modules/next/dist/docs/`. `cacheComponents` is off; pages that read the DB are dynamic.
- SQLite via better-sqlite3, synchronous. Helpers in `src/lib/db.ts`: `all`, `get`, `run`, `parse`,
  `newId`. Structured data lives in JSON TEXT columns. Core tables are in `db.ts`; area-specific
  tables/columns go in `src/lib/schema/{studio,courses,journeys}.ts`.
- Amazon Bedrock through `src/lib/llm.ts`: `chatJSON` (structured output through a forced tool),
  `chatText`, `chatStream`. Models: `MODELS.fast` (Haiku 4.5), `MODELS.chat` (Sonnet 4.5),
  `MODELS.smart` (Sonnet 5). Opus and the 5.5 models are blocked on this AWS account.
- Auth: `src/lib/auth.ts`. Pages call `requireUser()` / `requireUser("faculty")`; route handlers
  call `apiUser()` / `apiUser("faculty")` and return the Response if they get one.

## Core concepts (read `src/lib/types.ts` first)

- `CaseProfile`: a patient case as pure data: persona, `facts` (each with a disclosure `tier`),
  `actions` (exams/orders with fixed approved results), `artifacts` (EHR documents, tables, charts),
  `objectives`, `answerKey`, `knowledge`. Stored in `cases.profile`. Generated by
  `generateCase()` in `src/lib/casegen.ts`, cleaned by `normalizeCase()`.
- Encounter engine, `src/lib/engine/`:
  - `gatekeeper.ts`: a fast model proposes which locked facts the student asked about;
    `decide()` (deterministic) applies tier + rapport + difficulty rules.
  - `patient.ts`: patient prompt. The model only ever sees disclosed facts.
  - `encounter.ts`: `createEncounter`, `runTurn` (streaming), `runAction`, `hint`, `rewind`,
    `chartView` (the only view of a case a student may receive).
  - `feedback.ts`: `scoreEncounter` (ledger-based elicited/missed + rubric scoring with grounded
    evidence), `attemptHistory`.
  - `difficulty.ts`: `knobsForLevel(1..5)`, persona `PERTURBATIONS`.
- `src/lib/adaptive.ts`: Elo-style learner model: `recordSkill`, `skillProfile`, `recommend`.
- `src/lib/professions.ts` reads the role catalog `data/professions.json`.
- `src/lib/rubrics.ts`: built-in rubrics plus custom ones in the `rubrics` table.

## Conventions

- Never send a full `CaseProfile` to a student browser. Faculty pages may.
- Any request that waits on a slow model call (>20 s: case generation, scoring, synthesis) must
  return `longJson(() => ...)` from `src/lib/http.ts`. CloudFront drops silent connections at 60 s.
  The client just does `await res.json()` and checks for `.error`.
- Uploads go under `process.env.UPLOAD_DIR || data/uploads`.
- UI: reuse `src/components/ui.tsx` (Button, LinkButton, Card, CardHeader, Badge, Input, Textarea,
  Select, Label, PageHeader, Empty) and wrap pages in `AppShell`. Light theme, `brand-*` teal
  accent, slate neutrals. Plain, specific UI copy; no emoji.
- Clinical content shown to students must come from approved case data, never free model output.
- AI-written cases are stored with `origin = 'ai_draft'`, `reviewed = 0` and labelled as such.

## Running

```
npm install
cp .env.example .env.local   # AWS credentials with Bedrock + Polly access, SESSION_SECRET
npm run dev
```

Demo accounts (password `poscere-demo`): `faculty@poscere.demo`, `student@poscere.demo`,
`dietetics@poscere.demo`, `nursing@poscere.demo`. Seed cases load from `data/seed/cases/*.json`
on boot (`src/lib/seed.ts`).

Several dev servers can share the checkout:
`NEXT_DIST_DIR=.next-a DB_PATH=/tmp/a.db npx next dev -p 3101`.

Engine smoke test: `npx tsx --env-file=.env.local scripts/sim-test.ts`.

## Deployment

EC2 behind CloudFront. A systemd timer on the server polls `main` on GitHub every minute, builds
the new commit in its own release directory and switches over. `GET /api/health` reports the
running commit.

## Dataset-grounded patients

A patient's blood glucose, HbA1c, lipids, haemoglobin, MCV and blood pressure can be taken from a
row of the organisers' health-markers dataset instead of being written by the model.

- Put the file at `data/private/health_markers_dataset.csv` (gitignored) or set `HEALTH_MARKERS_CSV`.
  Without it the option does not appear and generation works as before.
- In **New patient**, choose a condition under **Clinical values from data**. The server picks a
  random complete row with that label (`src/lib/markersData.ts`), tells the model the values so
  the story fits them, and then writes them into the case itself (`applyMarkers` in
  `src/lib/markers.ts`): a "Laboratory results" document and "Blood tests" and "Blood pressure"
  actions. The row number is stored on the case as `dataSource`.
- The consistency check fails with a high-severity issue if those values are later changed, and
  lists any other record in the case that gives a different number for the same test.
- Units and reference ranges are standard adult values supplied in `markers.ts`; the dataset has
  numbers only. Rows with a missing marker are not used.
